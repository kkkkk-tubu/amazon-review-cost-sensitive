## 2. 数据质量诊断

诊断聚焦五类问题，统计基于**原始** 568,454 条。

### 2.1 重复记录（最主要问题）

| 判定口径 | 重复行数 | 去重后余量 |
|---|---|---|
| 除 Id 外全部字段一致 | 281 | 568,173 |
| **UserId + ProfileName + Time + Text（本流程采用）** | **174,521** | **393,933** |
| UserId + Time + Text | 174,562 | 393,892 |
| UserId + ProductId + Time + Text | 1,205 | 567,249 |
| Summary + Text | 173,484 | 394,970 |
| Text 全局一致（最激进） | 174,875 | 393,579 |

重复量集中在「同一用户、同一时间点、同一段文本」这一形态，共 17.4 万条，占原始数据 **30.7%**。结合 `Time` 精确到日这一粒度，可以判定这批记录来自数据源的多轮爬取合并，而非真实的多条独立评论——**必须去重，否则同一段文本会同时出现在训练集与测试集，造成严重的信息泄漏**。

### 2.2 逻辑非法与越界

- `HelpfulnessNumerator > HelpfulnessDenominator`：2 条。处理方式为置分子 = min(分子, 分母)，不删除样本。
- 越界时间戳：0 条。
- Score 越界：0 条。

### 2.3 文本噪声

| 噪声类型 | 涉及 Text 条数 | 占比 |
|---|---|---|
| HTML 标签（主要是 `<br />`） | 147,324 | 25.9% |
| HTML 实体（`&amp;` `&lt;` `&quot;` 等） | 1,857 | 0.33% |
| 裸 URL | 11,679 | 2.1% |
| 连续多空格 | 276,677 | 48.7% |
| 非 ASCII 字符 | 1,083 | 0.19% |
| 文本长度 > 5,000 字符 | 298 | 0.05% |

四分之一的评论带 `<br />`，是本品类数据集最典型的脏数据形态，直接进入分词会得到 `br` 这类无意义 token。

### 2.4 评分噪声（文本与星级不一致）

去重后，**相同规范化文本被赋予不同二分类标签**的共 **22 组、27 条**（若把中性 3 计入冲突判定则为 45 条）。占比极低（< 0.01%），说明该数据集的星级与文本一致性较高。已通过 `label_conflict` 布尔列标记，供错误分析与噪声鲁棒性实验直接取用。

### 2.5 跨用户的重复文本

去重后仅剩 **743 组**文本被多个用户提交（覆盖 1,562 行），最大一组 13 条。进一步核查发现这些是**真实的产品信息类长文**（例如某茶厂参观经历、杏仁营养说明），用户在不同产品下重复检索粘贴，不是模板水军。因此不删除，仅通过 `dup_group` 标记，在切分阶段保证同组不跨集合。

## 4. 去重口径的敏感性说明

去重口径直接决定样本量，属需要显式论证的选择，本流程的处理是：

1. **主口径采用 `UserId + ProfileName + Time + Text`**，与 Kaggle 社区通用做法一致，便于与他人结果对齐。
2. **不用 `Text` 全局去重作为默认**：该口径会额外删除 354 条同文本、不同用户、不同时间点的记录，其中包含真实的长文信息分享，过度删除会损失样本且削弱长度维度的试验空间。
3. **不做 UserId + ProductId 级别的折叠**（同口径会删 7,650 条）：同一用户多次购买同一产品并分别评论属合法行为。

`UserId + Time + Text` 口径比默认口径多删 41 条，两者最终样本量相差 0.01%，**说明主口径的结论对具体键的选取不敏感**——这一点需要在论文中说明，以回应「去重是否人为压低了数据量」的质疑。

去重后仍保留 `dup_group`（规范化文本的 MD5 前 10 位）与 `UserId` 两列，用于切分阶段的防泄漏约束，见第 8 节。

## 5. 标签构建

```python
label = 0  (负)   if Score in {1, 2}
label = 1  (正)   if Score in {4, 5}
label = 2  (中性) if Score == 3
```

三点必须写进论文的声明：

1. **标签来自星级评分，不是人工标注。** 因此标签的语义是「用户给出的整体满意度」，而非严格意义上的文本情感极性。用户可能因物流、包装等文本之外的因素给出低星，或出于礼节用词温和却给低星——这类样本构成模型精度上限的一部分。
2. **Score=3 不进入基础二分类实验**，剔除 29,769 条，占原始 5.24%。该部分数据保留在 `Reviews_clean.csv` 中，可用于「评分 3 的处理方式」这一拓展分析（可作三分类、可归入负面、或直接丢弃，三者的对比即为一项消融实验）。
3. 样本量变化已全程记录，符合「剔除并记录数量」的要求。

## 6. 文本规范化与预处理决策

### 6.1 处理顺序与做法

| 步骤 | 处理 | 理由 |
|---|---|---|
| 1 | HTML 反转义 + 剥离标签 | `<br />` 占 25.9%，否则产生 `br` 噪声 token |
| 2 | 剥离 URL 与 `www.` 链接 | 11,679 条含链接，域名对情感无判别力 |
| 3 | 缩写否定还原 | 见 6.2 |
| 4 | 统一小写 | `Good`/`good` 合并；本任务无需要保留大小写的实体 |
| 5 | 标点归一：`!` `?` 单独成 token，其余标点替换为空格 | 感叹号与问号携带情感强度，其余标点（逗号、引号、括号）对词袋模型无增益，保留会切碎 token |
| 6 | 压缩连续空白 | 48.7% 的文本存在多空格 |

处理结果抽样：

```
原始: I have bought several of the Vitality canned dog food products... My Labrador is finicky and she appreciates this product better than  most.
规范: i have bought several of the vitality canned dog food products ... my labrador is finicky and she appreciates this product better than most

原始: Product arrived labeled as Jumbo Salted Peanuts...the peanuts were actually <b>small</b> sized unsalted
规范: product arrived labeled as jumbo salted peanuts the peanuts were actually small sized unsalted
```

### 6.2 否定词处理（本实验的强制要求）

否定表达是情感分类的关键失效点：`not good` 与 `good` 在词袋中共享 `good` 这一维度，若不处理，模型会把否定句当作正面。本流程采取两层处理：

**第一层，缩写展开。** `n't` 结尾的否定缩写会被分词器切成 `don` + `t`，否定语义直接丢失。因此显式映射 20 组否定缩写：

```
don't → do not      can't → can not     won't → will not
isn't → is not      didn't → did not    couldn't → could not
...
```

**第二层，否定作用域标注。** 生成 `tokens_neg` 列，将否定触发词（`not` `no` `never` `nor` `nothing` `none` `neither` `hardly` `barely` `rarely` `cannot`）之后 3 个词加 `NEG_` 前缀：

```
you will not be disappointed at all
→ you will not NEG_be NEG_disappointed NEG_at all
```

这样 `NEG_disappointed` 与 `disappointed` 在特征空间中成为两个独立维度，模型无需自己学出否定与情感词的组合规律。全量数据中 **63.3%** 的评论至少含一处否定作用域标注（230,641 / 364,163），说明该处理覆盖面足够广，不是边缘 case。

该列同时是成员 A（否定词加权方案）与本人（不平衡条件下的否定样本误分分析）的直接输入。

### 6.3 停用词表的选择

**结论：默认提供两个版本，主实验用「去停用词」版本，对照实验用「含停用词」版本。**

- 停用词表的构造：内置 127 个英文高频功能词（无网络依赖，保证可复现），**基础词表中不含任何否定词**，并用 `STOPWORDS = BASE_STOPWORDS - NEGATIONS` 这一显式减法维持该不变量（`NEGATIONS` 收录 14 个否定/否定副词，当前与基础词表交集为空，作用是防止后续扩充词表时误加）。若直接使用 NLTK 默认英文停用词表，`not` `no` `nor` `neither` `never` 会被删除，与「注意保留否定词」的要求直接冲突——这也是很多课程作业在负面评论上召回率偏低的原因之一。
- 影响量化：去除停用词后，词数中位数由 57 降至 29，p95 由 215 降至 113，**平均保留 52.0% 的 token**。一方面显著压缩特征维度与训练开销，另一方面会移除 `the` `is` 这类高频低判别力词对 TF-IDF 的干扰。
- 风险与对照：停用词中 `no`（出现在 "no good"）、`very` `really`（程度副词，影响强度）实际携带信息。因此**必须做对照**：以「去停用词 TF-IDF」为基线，与「含停用词」版本在同一划分、同一随机种子下比较 F1，若含停用词版本更优，则说明该数据集上停用词处理应放弃。这构成一项消融实验。

处理列已就绪，直接在建模阶段切换即可：

| 列名 | 内容 |
|---|---|
| `tokens` | 分词后保留停用词 |
| `tokens_nostop` | 分词 + 去停用词（保留否定词） |
| `tokens_neg` | 分词 + 否定作用域标注（保留停用词，便于与 A 的加权方案对接） |

## 7. 数据探索结论

图表位于 `reports/figures/`。

### 7.1 评分分布与类别不平衡（fig1 / fig2）

星级呈极强右偏：5 星占 63.71%，1–5 星的比值约 1 : 0.57 : 0.82 : 1.54 : 6.91。

二分类后正负比 **5.38 : 1**，少数类（负面）仅占 **15.68%**。这意味着：

- 多数类基线 Accuracy 已达 **0.8432**。一个把全部样本判为正面的空模型就能拿到 84.3% 的准确率，**准确率在本任务上不具备区分能力**，必须以少数类召回率与宏平均 F1 为主指标。
- 这是本人研究方向（代价敏感学习 / Focal Loss）的直接动机：标准交叉熵在 5.38:1 的比例下会持续向多数类倾斜。

### 7.2 文本长度（fig3）

| 分位 | min | p5 | p25 | 中位 | p75 | p95 | max |
|---|---|---|---|---|---|---|---|
| 词数（含停用词） | 3 | 21 | 35 | 58 | 100 | 219 | 3,476 |
| 词数（去停用词） | 1 | 11 | 18 | 30 | 51 | 115 | 2,053 |

长度跨度接近三个数量级，属长尾分布。**按维度做定长截断时需注意代价：统一截断到 256 词会损失 3.13% 的样本，截断到 300 词损失 2.00%**；建议改用截断 + 分桶统计的组合，或在成员 C 的序列模型上单独讨论长评处理。

正负类长度存在系统性差异：**负面评论平均 87.0 词，正面评论平均 78.7 词；中位数 65 词 vs 55 词**。负面评论更长、更倾向于详细陈述问题，这既是不平衡的一种表现形式，也意味着「长度」本身是一个弱判别特征——需要警惕模型学到「长 = 负面」这种伪相关。

### 7.3 长度与极性的非线性关系（fig5）——需重点关注的发现

| 词数区间 | 样本量 | 占比 | 正面比例 |
|---|---|---|---|
| ≤20 | 15,120 | 4.2% | **0.9054** |
| 21–50 | 145,425 | 39.9% | 0.8635 |
| 51–100 | 116,474 | 32.0% | 0.8281 |
| 101–200 | 65,582 | 18.0% | **0.8169** |
| 201–400 | 18,529 | 5.1% | 0.8241 |
| >400 | 3,033 | 0.8% | 0.8223 |
| 整体 | 364,163 | 100% | 0.8432 |

正面比例随长度**先降后升**，最低点落在 101–200 词区间（0.8169），并非单调关系。短评（≤20 词）正面率高达 90.5%，多数是「Great product」式的满意表态；中等长度评论最可能出现详细抱怨。

**这条结论对三项拓展分析都很关键**：按长度分层评估模型性能时，分层的类别先验本身不同，不能直接把各层 F1 横向比较；做代价敏感加权时也不能假设误报成本在长度维度上均匀。

### 7.4 随时间的变化（fig4）

| 年份 | 2004 | 2006 | 2008 | 2010 | 2011 | 2012 |
|---|---|---|---|---|---|---|
| 样本量 | 431 | 4,482 | 21,624 | 53,848 | 104,333 | 128,208 |
| 正面比例 | 0.930 | 0.868 | 0.889 | 0.850 | 0.834 | **0.825** |

两个特征值得记录：

1. **样本量逐年暴增**，2011–2012 两年占清洗后总量的 59.5%。随机划分时训练集天然偏向晚期评论。
2. **正面比例持续下滑**，从 2004 年的 93.0% 降至 2012 年的 82.5%，降幅 10 个百分点以上。

因此「按时间划分 vs 随机划分」不是形式上的对照：随机划分会把同期同产品的评论分散到训练与测试两侧，分数会明显优于时间划分，两者之差即为**时序漂移带来的乐观偏差**。建议将按 `Year` 的时间划分结果作为主表，随机划分作为对照，并在论文中给出两者的差值。

## 8. 划分与防泄漏协议

清洗阶段已为切分准备好三列，建模阶段**必须**按以下约束划分：

| 列 | 用途 |
|---|---|
| `dup_group` | 相同规范化文本的组标识。分组切分（`GroupShuffleSplit`），保证同组不跨集合 |
| `UserId` | 用户级切分，防止同一用户的多条评论跨集合（用户写作风格会被模型记忆） |
| `Year` | 时间划分，用于时序泛化对照 |

划分比例与顺序：**先划分、后做任何依赖全局统计的变换**（TF-IDF 词表、IDF 权重、标准化参数一律只在训练集上拟合），避免验证/测试信息泄漏。随机种子固定为 42，多随机种子实验在此基础上叠加。

需说明的取舍：严格采用 `dup_group` 分组切分，去重后仅剩 743 组重复文本，对最终分数影响有限（1,562 / 364,163 = 0.43% 样本），但满足了实验要求的防泄漏约束；用户级切分则影响更大——清洗后二分类集含 243,411 个用户，其中 96 个用户评论数 ≥ 50（最多者 310 条），共覆盖 7,692 行（2.11%）。这些高频用户若不隔离，其写作风格会被模型记忆并明显拉高同分布测试的分数。

## 附：已知局限

1. `ProfileName` 存在同一 `UserId` 对应多个昵称的情况（50 例）。默认去重口径含该字段，理论上会漏掉极少量「同人改名后重复提交」的记录，实测影响 < 0.01% 样本。
2. `Time` 粒度为日，同日提交的不同评论无法区分先后，「同一时刻」实际指同一日期。
3. 否定作用域固定窗口为 3 词，未处理跨标点的长距离否定与双重否定（如 `not unlikely`）。该简化在缩略评论上成立，长评上可能漏标，可作为改进点交成员 A。
4. 停用词表为内置 148 词表，与 NLTK / scikit-learn 的默认表不完全一致，跨组对比时需统一到同一份词表。
